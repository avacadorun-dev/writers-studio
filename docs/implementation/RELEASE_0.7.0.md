# Release 0.7.0 — удобство редактора и ассистента

Дата планирования: 2026-08-27. Дата реализации и deployment: 2026-08-28.
Статус: **implemented, verified and deployed** на
[`studio.example.test`](https://studio.example.test).

Production deployment выполнен на `127.0.0.1` с server-side backup
PostgreSQL и MinIO до switch. Сохранены rollback image и полный
source-каталог до 0.7.0. После switch `app`, `db` и `storage` healthy,
HTTPS health и SPA routes возвращают `200`, а production browser загружает
новый asset `index-B05Pzt2n.js` без console errors.

Источник обратной связи: [Figma — Untitled](https://www.figma.com/design/9PlJTVQQnDykQX4IZOrwul/Untitled?node-id=0-1&p=f).

## Цель релиза

Сделать основные авторские сценарии понятными без поиска функций по скрытым меню:

- дать быстрый и предсказуемый доступ к форматированию и типографике;
- исправить дефекты ввода, переполнение и нестабильное позиционирование элементов;
- привести Assistant в Studio, Canvas и review к одной модели панели и прокрутки;
- сохранить существующие гарантии autosave, revisions, undo и безопасного применения
  предложений.

Релиз не меняет модель владения данными, правила применения Assistant change set и
разделение настроек редактора и экспортного профиля.

## WS-0701 — Адаптивный и настраиваемый тулбар редактора

**Проблема.** Подчёркивание, зачёркивание, inline-код, цитаты и списки находятся в
меню `Дополнительное форматирование`. При доступной ширине панели пользователь не
видит эти возможности и обнаруживает их случайно.

**Ожидаемый результат.** На широком экране основные текстовые действия видны сразу.
На узком экране тулбар компактно сворачивает действия без clipping и горизонтальной
прокрутки. Пользователь может переопределить автоматический режим.

**Объём.**

- добавить режимы тулбара `Авто`, `Расширенный`, `Компактный` в writer preferences;
- в `Авто` раскрывать все базовые text marks и списки при достаточной ширине;
- сохранять вставку сложных блоков в отдельном меню `Вставить блок`;
- оставить overflow-меню для компактных viewport и редких действий;
- показывать tooltip, активное состояние и доступное имя для каждой icon-кнопки.

**Критерии приёмки.**

1. При ширине workspace от 1280 px видны: курсив, полужирный, подчёркивание,
   зачёркивание, inline-код, цитата, маркированный и нумерованный списки.
2. На 1024 px и меньше действия, которые не помещаются, переходят в одно
   overflow-меню; сам тулбар не выходит за границы редактора.
3. В режиме `Расширенный` разрешён перенос на вторую строку, но редактор не
   перекрывается и высота workspace пересчитывается.
4. Выбранный режим сохраняется после reload и применяется ко всем документам.
5. Все действия доступны с клавиатуры, имеют `aria-label` и показывают
   `aria-pressed`, когда формат активен.
6. Команды Tiptap, undo history и autosave работают так же, как до изменения.

**Проверка.** Component tests для трёх режимов и active state; Playwright на
1440×1024, 1024×768 и 390×844; keyboard pass по всем действиям тулбара.

**Точки реализации.** `src/features/editor/ui/formatting-toolbar.tsx`,
`src/shared/lib/preferences.ts`, `src/pages/settings/ui/settings-page.tsx`,
`src/shared/styles/globals.css`.

## WS-0702 — Drag-and-drop изображений в рукопись

**Проблема.** Пользователь ожидает прикрепление изображения через drag-and-drop,
но текущий путь доступен только через скрытое меню и file picker.

**Ожидаемый результат.** Изображение можно перетащить в нужное место рукописи;
результат идентичен вставке через `Вставить блок → Изображение`.

**Объём.**

- принимать локальные PNG, JPEG и GIF в области редактора;
- показывать drop indicator в вычисленной позиции документа;
- использовать существующий private project media upload и `imageBlock`;
- сохранить file picker как равноправный доступный путь;
- не добавлять произвольные вложения в Assistant в рамках этой задачи.

**Критерии приёмки.**

1. Во время dragover редактор показывает одну однозначную точку вставки.
2. Валидный файл до 12 MiB загружается в текущий проект и вставляется в выбранную
   позицию с новым `blockId`.
3. Невалидный тип, слишком большой файл и ошибка сети показывают понятную ошибку;
   JSON документа и revision при этом не меняются.
4. До durable upload в документ не записывается битая ссылка на media.
5. После успешной вставки доступны существующие alt-текст, подпись, autosave,
   export/import и recovery.
6. Drop не перехватывает перенос текста и внутреннее перетаскивание блоков.

**Проверка.** Unit tests классификации drop; component test upload/error;
Playwright с `DataTransfer` для успешного и отклонённого файла; reload после
autosave.

**Точки реализации.** `src/widgets/manuscript-editor/ui/manuscript-editor.tsx`,
`src/features/editor/model/rich-blocks.tsx`, `src/entities/project/api/project-api.ts`.

## WS-0703 — Быстрые настройки интервалов текста и списков

**Проблема.** Межстрочный интервал доступен только в общих настройках, а интервал
между абзацами и плотность списков не регулируются отдельно. Из-за одинакового
`margin` абзацев списки выглядят чрезмерно разреженными.

**Ожидаемый результат.** Типографику можно настроить из редактора, не покидая
документ. Интервалы обычного текста и элементов списка управляются независимо.

**Объём.**

- добавить popover `Типографика` в тулбар с быстрым доступом к существующему
  `lineHeight`;
- добавить preferences `paragraphSpacing` (`0.65 / 0.9 / 1.1 em`) и
  `listItemSpacing` (`0 / 0.25 / 0.5 em`);
- применить отдельные CSS variables к обычным абзацам и `li > p`;
- продублировать настройки на странице `Настройки → Редактор`;
- не сериализовать presentation preferences в canonical document и не менять
  export profile.

**Критерии приёмки.**

1. Изменение любого интервала сразу отражается на открытом документе.
2. Настройки сохраняются после reload и проходят нормализацию старого storage.
3. Плотность списка меняется без изменения расстояния между обычными абзацами.
4. Вложенные списки, callout, таблицы и code block не получают двойные отступы.
5. Значения по умолчанию визуально плотнее текущего `1.1em`, но существующий
   `lineHeight=1.75` сохраняется при миграции настроек.
6. Экспортные настройки DOCX/Markdown/TXT остаются независимыми.

**Проверка.** Tests нормализации preferences и CSS variables; component test
popover; visual assertions для абзацев, ordered/unordered и вложенного списка.

**Точки реализации.** `src/shared/lib/preferences.ts`,
`src/features/editor/ui/formatting-toolbar.tsx`,
`src/pages/settings/ui/settings-page.tsx`, `src/shared/styles/globals.css`.

## WS-0704 — Формулы inline и отдельным блоком

**Проблема.** Редактор не поддерживает формулы: пользователю приходится оставлять
сырой LaTeX или изображение, что плохо редактируется и экспортируется.

**Ожидаемый результат.** Пользователь может вставить и отредактировать короткую
формулу в строке и отдельную display-формулу с сохранением исходника.

**Объём.**

- добавить `inlineMath` и `mathBlock` в editor schema;
- вставлять формулу из тулбара, командой и через paste `$…$` / `$$…$$`;
- хранить исходный LaTeX, рендерить его безопасным клиентским renderer без
  выполнения HTML/JS и сетевых запросов;
- добавить редактирование исходника, fallback при ошибке и доступное текстовое
  описание;
- сохранить обратную совместимость старых revisions и `.wstudio` import;
- экспортировать Markdown как `$…$`/`$$…$$`, а TXT/DOCX — как безопасный
  текстовый fallback с исходником.

**Критерии приёмки.**

1. Inline-формула участвует в обычном потоке строки; block-формула занимает
   отдельный редактируемый блок.
2. Невалидный LaTeX не ломает документ и показывает исходник с ошибкой.
3. Renderer не допускает trusted HTML, внешние URL и пользовательские команды,
   способные выполнить код.
4. Формула переживает autosave, versions, duplicate, assistant proposal,
   export/import и restore.
5. Copy/paste и undo/redo не теряют исходник и `blockId`.
6. Screen reader получает исходник или заданное пользователем описание.

**Проверка.** Schema/transaction tests, sanitizer tests, UI tests валидной и
ошибочной формулы, export/import compatibility, Playwright insert-edit-reload.

**Точки реализации.** `src/features/editor/model/extensions.ts`, новый math
NodeView рядом с `rich-blocks.tsx`, `formatting-toolbar.tsx`, backend document
allowlist и export serializers.

**Вне объёма.** Визуальный конструктор формул, CAS-вычисления и нумерация формул.

## WS-0705 — Формирование inline-кода независимо от порядка ввода backtick

**Проблема.** Если пользователь сначала ставит закрывающий backtick, а затем
открывающий, готовая пара не превращает текст в inline-код. Миграция сохранённого
JSON не исправляет интерактивный ввод.

**Ожидаемый результат.** Полная согласованная пара backtick преобразуется в mark
`code` независимо от того, какой разделитель был введён последним.

**Критерии приёмки.**

1. Сценарий «сначала backtick справа, затем слева» и обычный сценарий «сначала
   слева, затем справа» дают одинаковый inline-code mark без отображаемых
   разделителей.
2. Поведение работает в середине и в конце абзаца, рядом с другими marks и после
   paste.
3. Незакрытая пара, экранированный backtick, code block и несовпадающие серии
   backtick не преобразуются.
4. Одно Undo возвращает состояние до автоматического преобразования.
5. Автосохранение не создаёт промежуточную revision только из-за внутренней
   нормализации transaction.
6. Существующая миграция старых документов остаётся идемпотентной.

**Проверка.** Transaction tests для обоих порядков ввода, marks, paste, undo и
негативных случаев; browser test реального набора текста.

**Точки реализации.** `src/features/editor/model/code-block.tsx`,
`src/features/editor/model/code-block.test.ts`, editor input rules/plugins.

## WS-0706 — Видимые границы рабочей ширины рукописи

**Проблема.** В integrated workspace текст ограничен `60/70/80ch`, но пустое
пространство вокруг никак не объясняет ограничение. Пользователь воспринимает это
как случайно неиспользованную часть экрана.

**Ожидаемый результат.** Рабочая колонка рукописи визуально считывается как
намеренная область набора, не превращая интерфейс в имитацию бумажного листа.

**Критерии приёмки.**

1. У колонки есть спокойная граница или gutter, различимая во всех темах и не
   мешающая чтению.
2. Переключение `60/70/80 знаков` сразу и предсказуемо меняет видимую колонку.
3. Заголовок документа, editor content, proposal preview и статус-бар используют
   одну горизонтальную сетку.
4. Открытие docked Assistant не меняет значение настройки и не обрезает текст.
5. На mobile отдельная декоративная граница исчезает, остаётся доступный padding.
6. Нет горизонтального overflow на поддерживаемых viewport.

**Проверка.** Visual regression для трёх ширин, светлой/тёмной темы, Assistant
open/closed и 390×844.

**Точки реализации.** `src/widgets/manuscript-editor/ui/manuscript-editor.tsx`,
`src/shared/styles/globals.css`.

## WS-0707 — Выравнивание empty state, заголовков, каретки и быстрых действий

**Проблема.** Empty-state действия позиционируются абсолютно, из-за чего визуально
конфликтуют с первой строкой. При выборе `Заголовок 1` большая каретка и кнопки
`Начать писать` / `Диктовать` оказываются на разных, случайных осях; заголовок и
редактируемый текст также могут расходиться по горизонтали.

**Ожидаемый результат.** Empty state является частью потока редактора, а первая
каретка всегда начинается на общей сетке рукописи.

**Критерии приёмки.**

1. Быстрые действия размещены отдельным блоком между metadata/header и первым
   редактируемым абзацем, а не поверх editable content.
2. `Начать писать` ставит каретку в первый текстовый блок; `Диктовать` сохраняет
   текущий destination.
3. После первого символа empty-state действия исчезают без скачка scroll position.
4. Каретка в paragraph, H1, H2 и H3 выровнена по границе editable column и не
   пересекается с кнопками.
5. Верхний заголовок материала и содержимое не создают впечатление двух
   конкурирующих H1; screen reader получает однозначную структуру headings.
6. Поведение одинаково во floating и integrated workspace.

**Проверка.** Component tests focus/caret; Playwright keyboard flow; screenshots
пустого paragraph/H1 и документа с первым символом.

**Точки реализации.** `src/widgets/manuscript-editor/ui/manuscript-editor.tsx`,
`src/shared/styles/globals.css`.

## WS-0708 — Стабильный статус-бар редактора

**Проблема.** Счётчик слов расположен после content и в коротком документе визуально
«висит» в середине полотна. Доступ к источнику перемещается вместе с ним.

**Ожидаемый результат.** Служебная информация имеет постоянное место и не
конкурирует с рукописью.

**Критерии приёмки.**

1. Счётчик слов и действие источника находятся в отдельном status bar у нижней
   границы editor surface.
2. Status bar виден в коротком документе, не перекрывает последнюю строку длинного
   документа и не участвует в прокрутке текста.
3. Значение обновляется после transaction без заметной задержки.
4. В focus mode, integrated workspace и mobile сохранены доступные label и
   keyboard focus.
5. При отсутствии source action полоса не меняет высоту и выравнивание.

**Проверка.** Component tests empty/long/source; E2E scroll до конца документа на
desktop и mobile.

**Точки реализации.** `src/widgets/manuscript-editor/ui/manuscript-editor.tsx`.

## WS-0709 — Быстрое переименование материалов

**Проблема.** Переименование спрятано в меню строки дерева. Для частой операции
нужен прямой путь; постоянно видимое `…` создаёт лишний визуальный шум.

**Ожидаемый результат.** Материал можно переименовать двойным кликом по имени в
дереве и по заголовку активного файла, с тем же backend mutation и validation.

**Критерии приёмки.**

1. Double-click по label дерева или заголовку активного материала включает inline
   edit без перехода по route.
2. `Enter` сохраняет, `Escape` отменяет, пустое/невалидное значение не отправляется.
3. `F2` запускает переименование выбранного treeitem; существующий menu item
   остаётся доступным.
4. Кнопка `…` видна для selected, hover и focus-within строки; скрытие не удаляет
   её из keyboard tab order в момент работы пользователя.
5. После success синхронно обновляются дерево, breadcrumb, workspace header и
   кэш проекта без remount редактора и потери selection/undo.
6. Ошибка сервера возвращает исходное имя и показывает понятный toast.

**Проверка.** Component tests edit lifecycle и focus; API mutation test;
Playwright rename из дерева, header, F2, cancel и error.

**Точки реализации.** `src/widgets/project-tree/ui/project-tree.tsx`,
`src/widgets/workspace-header/ui/workspace-header.tsx`, project query cache.

## WS-0710 — Единый docked Assistant shell в Studio и Canvas

**Проблема.** В Studio Assistant выглядит как боковая панель, а на Canvas — как
плавающее окно с произвольными отступами и радиусом. Один и тот же run воспринимается
как разные инструменты.

**Ожидаемый результат.** Studio и Canvas используют одну визуальную и
интеракционную модель docked-панели. Отличается только контекст цели.

**Объём.**

- вынести общий shell для session/thread switcher/new chat;
- на desktop dock Canvas занимает правый край workspace под общим header и не
  накрывает содержимое доски;
- на tablet использовать управляемый overlay от правого края, на mobile —
  существующее полноэкранное presentation state;
- сохранить один `AssistantRun` при переходе Studio ↔ Canvas.

**Критерии приёмки.**

1. Header, ширина, разделители, close/new/thread controls и состояния панели
   совпадают в Studio и Canvas.
2. На Canvas панель не имеет случайных внешних отступов/плавающей тени и не
   перекрывает tool rail.
3. Открытие dock не меняет координаты canvas nodes; viewport корректно
   пересчитывается и закрытие возвращает доступную ширину.
4. Run history, draft, mode, target, selection/canvas context и scroll position
   сохраняются при переключении surface.
5. Background run не останавливается при закрытии панели.
6. Focus при открытии и закрытии возвращается в вызвавший control.

**Проверка.** Shared shell tests; Playwright Studio/Canvas switch с одним run;
responsive pass 1440, 1024, 834 и 390 px.

**Точки реализации.** `src/pages/assistant-session/ui/assistant-session-page.tsx`,
`src/pages/canvas/ui/canvas-page.tsx`, `src/pages/studio/ui/studio-page.tsx`,
`src/widgets/assistant-threads/`.

## WS-0711 — Изолированная прокрутка Assistant и review

**Проблема.** При длинной истории или контексте прокручивается вся страница вместо
feed/колонки. Header, composer и действия исчезают, а wheel может затронуть Canvas
под панелью.

**Ожидаемый результат.** Каждый длинный регион прокручивается внутри отведённой
области, при этом оболочка приложения остаётся фиксированной.

**Критерии приёмки.**

1. В Assistant прокручивается только transcript viewport; header, mode/target и
   composer/change-set actions остаются на месте.
2. В review независимо прокручиваются список групп, diff и контекст сессии; footer
   действий остаётся доступным.
3. На desktop `documentElement` не получает вертикальный или горизонтальный
   overflow из-за Assistant/review.
4. Wheel/touch внутри dock не pan/zoom Canvas и не прокручивает Studio за панелью.
5. Auto-follow работает только когда пользователь находится у конца feed;
   прокрутка вверх не сбрасывается новым event.
6. Scroll position хранится отдельно для каждого run и восстанавливается при
   переключении чатов.
7. На mobile прокручивается один предсказуемый content region без вложенной
   scroll trap.

**Проверка.** Unit tests near-end и scroll restoration; Playwright с длинным feed,
длинным review context, Canvas wheel isolation и mobile touch viewport.

**Точки реализации.** `assistant-session-page.tsx`,
`assistant-transcript-scroll.ts`, `assistant-review-page.tsx`, Canvas panel shell.

## WS-0712 — Безопасное отображение JSON и длинных сообщений

**Проблема.** Большой JSON и длинные непрерывные токены выходят за границы message
bubble, расширяют панель и делают историю нечитаемой.

**Ожидаемый результат.** Обычный текст, длинные строки и структурированные данные
никогда не ломают ширину Assistant; JSON остаётся читаемым и копируемым.

**Объём.**

- общий message renderer для embedded и standalone Assistant;
- valid JSON и fenced code показывать как code surface с внутренней прокруткой;
- длинный JSON сворачивать до preview с явным `Показать полностью`;
- plain text сохраняет переносы, а непрерывные токены используют
  `overflow-wrap:anywhere`;
- копирование возвращает точный исходный текст.

**Критерии приёмки.**

1. Message bubble всегда имеет `min-width: 0` и не шире transcript viewport.
2. JSON форматируется без изменения данных; кнопка копирования копирует исходник.
3. Code surface имеет собственный horizontal scroll, max-height и keyboard access.
4. Plain text с URL/ID длиннее ширины переносится, а не расширяет layout.
5. Collapse/expand не сбрасывает позицию общего feed.
6. Поведение одинаково для user instruction, assistant text и tool/event details.
7. Renderer не интерпретирует HTML и не выполняет содержимое сообщения.

**Проверка.** Component tests JSON/plain/fenced/malformed/HTML; snapshots compact и
standalone; Playwright assertion отсутствия horizontal overflow.

**Точки реализации.** Новый message renderer в `src/pages/assistant-session/`,
`assistant-session-page.tsx`, `assistant-review-page.tsx`.

## WS-0713 — Ясная визуальная иерархия проверки изменений

**Проблема.** На экране review одновременно конкурируют набор изменений, preview,
контекст сессии и сырые данные. С первого взгляда непонятно, что проверить и какое
действие является основным.

**Ожидаемый результат.** Review ведёт пользователя по последовательности
`статус → выбранные группы → точный результат → применить/исправить/отклонить`.

**Объём.**

- сохранить embedded modal как основной путь из docked Assistant;
- усилить summary состояния и выбранного scope в header;
- сделать diff/preview главным визуальным регионом;
- перенести сырую трассировку и полный контекст в сворачиваемые supporting regions;
- закрепить footer с взаимоисключающими primary actions.

**Критерии приёмки.**

1. При открытии видны title change set, статус `не применено/применено/отменено`,
   число выбранных групп и первый точный diff.
2. Главный CTA соответствует состоянию: `Применить изменения`, `Отправить
   замечания`, `Отменить набор` или `Вернуться` — одновременно показывается только
   один primary action.
3. Исключённая группа визуально отличается не только цветом; зависимости объяснены
   рядом с control.
4. Raw tool payload, JSON и полная трассировка закрыты по умолчанию, но доступны
   без перехода на другую страницу.
5. Footer остаётся видимым при прокрутке любой колонки и не закрывает последний
   diff.
6. `Попросить исправить` заменяет apply-actions формой `Отмена` / `Отправить` в
   соответствии с `ASSISTANT_MODE.md`.
7. Dialog имеет корректный focus trap, начальный focus, Escape/close и возврат
   focus в Assistant panel.

**Проверка.** Presentation model tests; accessibility/component tests dialog и
group selection; Playwright apply, partial apply, request changes, reject, undo;
visual regression desktop/tablet/mobile.

**Точки реализации.** `src/pages/assistant-review/ui/assistant-review-page.tsx`,
`src/pages/assistant-review/model/assistant-review-presentation.ts`.
