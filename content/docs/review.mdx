title: Reviewing changes
description: Read a precise comparison, refine proposals, and apply, reject, or undo assistant edits.
---

The review screen is where you make the final editorial decision. It shows removed and added passages separately, with unchanged text to help you locate the edit within the scene.

## Read the entire proposal

Recall the original task, then review every change from top to bottom. Check facts, the rhythm of nearby paragraphs, names, and connections as well as individual wording. Understand the role of each passage before applying a large proposal.

To refine the result, give a specific comment: “keep the comparison with the sea,” “keep the name,” or “shorten only the second line of dialogue.” A new proposal appears as a preview and requires confirmation before changing the manuscript.

## Apply or reject

**Apply** transfers the displayed edits to the document. Return to the editor, read the whole passage, and wait for saving to complete. **Reject** declines the proposal; the document text stays as it was and the decision is recorded in the work history.

A proposal may become outdated if the document changes after it was prepared. Compare the current passage, ask the assistant to prepare the proposal again, and review the new version.

## Undo an applied edit

Use the undo action immediately after applying if it is available. Later, open version history, select the state before the edit, and restore it as a new revision. Check nearby changes afterward: restoring a version can affect more text than a single proposal.

<Callout type="info" title="A useful question before applying">
  Can you explain what will change and why the new version works better for this scene? If you cannot, ask the assistant to clarify its proposal.
</Callout>
